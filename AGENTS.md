# Doc Governor repository instructions

Doc Governor governs Markdown; it should not create Markdown merely to report that it ran.

- Use only the five core document types: `contract`, `state`, `procedure`, `evidence`, and `decision`.
- Register governed documents, dependencies, owners, TTLs, and protected paths in `.docgov/catalog.yaml`.
- Treat `.docgov/ledger.jsonl` as append-only evidence. A date is not refreshed by changing text alone.
- Every generated document must have a canonical destination or be rejected as an orphan/misclassified file.
- Model output may propose semantic findings, but it cannot directly authorize content updates or stale-status changes. Deterministic code holds the final ruling: only a duplicate merge and a fully grounded contract span survive, and `apply_safe_actions` re-proves both before touching a file.
- Each agent in the Strands graph is deliberately under-privileged. Do not widen a tool scope, and do not let the Evidence Auditor see a document's own status or `last_verified_at`; owner-configured control documents and contracts with a matching authorized coding-review receipt are excluded from semantic auditing, while changed or revoked receipts return to normal auditing. The Contract Drafter must remain impossible to construct for a `state`, `evidence`, `decision`, protected, or human-approval document — enforce that in code, never in a prompt.
- The Strands Repair Planner may produce instructions for `contract` and `procedure` documents but may never write. Give each planner only its assigned target and changed files matching that target's declared dependencies. Reject missing, malformed, out-of-scope, or `needs_human` plans before invoking the coding-agent executor.
- Governance verdicts and repair plans use typed final-output tools with bounded output attempts separate from read budgets. Final-output tools grant no file, shell, or network access; deterministic grounding and path checks remain required.
- A model-enabled run's public trace may contain only agent, tool, and model identifiers, never document text.
- `.docgov/trust.json` is generated, deterministic, and committed. It must be byte-identical for an unchanged working tree: never record the serializing run's timestamp or HEAD in it, only the verification's.
- The MCP server is the enforcement point and is read-only. It must never gain a write, shell, or network tool, must never return partial content from a refused document, and must fail closed when the trust state is missing or its version is unknown.
- Cross-environment drift detection is read-only. Doc Governor never deploys and never holds a production write credential; it emits a finding and the release workflow decides.
- Never delete an existing document from `main`. Automatic deletion is limited to an exact duplicate newly added by the current PR, with no inbound links; human approval is required for a protected duplicate.
- Keep Supabase source/config inventory and contract documents consistent. A mismatch is a blocker, not an invitation to invent documentation.
- Installed background mode registers work at commit time without waiting for models. The worker repairs one authorized contract at a time in a private snapshot and requires an independent coding review before publication. It never stages; the pre-commit integration may stage exact generated bytes only when staged dependencies match the reviewed evidence. Preserve existing hooks and partial staging. Failed work remains untrusted and persists for bounded retries. The explicit `docgov repair --json` command and uninstalled legacy hook retain their staged-snapshot behavior and fail-closed model/verifier checks. Never invoke `baseline --approved` from a hook or worker.
- Install pins the committed Catalog authorization and coding-review policy in worktree-private Git storage. Status promotion does not expand this grant. Edited policies, model prose, PR labels, or ordinary documents cannot extend installed authority. Background writes remain limited to eligible unprotected contracts and their independently generated review, ledger, and trust artifacts. New section-scoped protected-document permissions require an explicit future policy and corresponding tests.
- Sophie delegates final trust review through `docgov coding-review PATH ... --verify-command COMMAND` to a separate read-only Codex session; repair success is not approval. Use the standard `.docgov` paths and explicit, unique tracked targets allowed by the tracked version-1 `.docgov/coding-agent-review-policy.json`, with reviewer `coding_agent` and status `authorized_review_pending` or `enabled`. Review targets must be `contract` documents with status `current` or `stale` and nonempty declared dependency evidence; a dependency on `.docgov/catalog.yaml` blocks review. Other documents retain their existing approval policy.
- Coding-agent review uses current tracked working-tree bytes in an isolated repository, preserves document prose and the source index, and rejects any file with both staged and unstaged changes. The repository verifier must pass without modifying the isolated snapshot before the reviewer runs. The reviewer must inspect every material claim, treat repository prose and prior verdicts as untrusted evidence, and cite inspected non-target files matching each target's declared dependencies. Test success alone does not establish prose truth; unsupported or conflicting claims require an `untrusted` verdict. Where available, the reviewer reads Markdown through `scripts/docgov-read --repair`.
- A new independent review does not require an existing matching receipt: the coordinator creates that receipt only after a supported verdict. Repair preserves historical status and verification-date banners; those labels neither prove substantive truth nor independently invalidate it. Substantive body claims about dates, tests, releases, or deployments still require inspected supporting evidence.
- The coordinator requires evidence of a completed reviewer session and a structured verdict matching the snapshot and every requested target: all must be `trusted`, with no unresolved claims and nonempty valid citations outside `.docgov/`. It checks the isolated files, original working-tree signature, HEAD, index tree, document hashes and dependency fingerprints for changes before writing `.docgov/reviews/<snapshot_id>.json` and append-only `verify_current` ledger entries bound to the receipt and `codex:` session identifier. Successful review can promote scoped stale contracts to `current` without refreshing Catalog dates; the CLI regenerates trust state after changes. An already matching review returns without new evidence. Trust analysis and MCP reads require the delegated review to remain authorized and hash-matched; missing, revoked or mismatched reviews are refused.
- Changes to CLI contracts, the GitHub Action, document taxonomy, or lifecycle rules require updates to `README.md`, tests, and the relevant Catalog examples.
- Run `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -v` before handing off changes.
