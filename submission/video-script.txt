00:00–00:30 — THE PROBLEM (no jargon, no product name)
------------------------------------------------------------------------------
ON SCREEN: a plain code editor with a Markdown file open next to a source file.

SAY:
  "When an AI writes code for you, it reads the notes in your repository first,
  and it believes them.

  Somebody changed this file three weeks ago. Nobody updated the notes. A person
  would probably notice something was off. The AI doesn't — it builds on the old
  information, confidently, and you find out in production.

  The person this hurts is whoever trusted the output."


00:30–00:50 — THE IDEA
------------------------------------------------------------------------------
ON SCREEN: title card, then the README's first line.

SAY:
  "The usual fix is a check that runs when someone opens a pull request. That
  only protects future commits. Every out-of-date document already merged into
  your main branch is still sitting there, still being handed to every AI agent,
  every day.

  So Doc Governor does something else. It doesn't try to make every document
  correct. It decides which documents an AI is allowed to read at all."


00:50–01:15 — HOW IT DECIDES
------------------------------------------------------------------------------
ON SCREEN: a catalog entry with depends_on, then a trust.json entry.

SAY:
  "A document says which source files it describes. When it's verified, we hash
  those files and store the hash.

  Not the date. The date is worthless — 'verified on the first' means nothing if
  the code changed on the third. We store what the code actually looked like.

  When an AI asks for the document, we hash those files again, right then, and
  compare."


01:15–02:05 — THE REPETITIVE JOB DISAPPEARS
------------------------------------------------------------------------------
ON SCREEN: change a declared source file, then run a commit with
DOCGOV_ENABLE_MODEL=1. Show the Repair Planner output and the staged doc diff.

SAY:
  "As a solo developer, this is the repetitive job I wanted gone. I finish a
  code change, then type 'update the docs' again and again.

  Doc Governor first finds the affected required documents with Git paths and
  hashes — zero model tokens. Only then does a read-only Strands Repair Planner
  on Amazon Bedrock produce evidence-bounded instructions. It can read only this
  document and changed files the catalog says it depends on.

  My existing Codex account executes the plan. The tests pass, and the repaired
  file is staged before commit.

  But the hook does not approve what Codex wrote. Tests prove that software runs;
  they do not prove that prose is true. A maintainer still owns that decision."


02:05–02:45 — THE READ GATE
------------------------------------------------------------------------------
RUN: python scripts/demo.py --keep

ON SCREEN: the "reads" array from the demo output, one entry at a time.

SAY:
  "Now the part that matters. An AI coding agent asks for documents through this
  server instead of opening files.

  [3-corrected-contract] The corrected API document: served. Three hundred and
  twenty characters of content.

  [3-unverified-state] The release note: refused. And look at what comes back —
  not an error. A reason, and a list of the source files to read instead. That
  matters, because a bare error just makes the agent go open the raw file, which
  is exactly what we're preventing.

  [3-merged-duplicate] And the duplicate we deleted still answers — it tells the
  agent which document absorbed it.

  served_characters is zero on both refusals. A refused document leaks nothing.
  Not a summary, not the first line."


02:45–03:25 — THE MOMENT  ← slow down here
------------------------------------------------------------------------------
ON SCREEN: split view. Left: the terminal. Right: supabase/config.toml.

SAY:
  "One more. The API document was trusted a second ago — you just watched it get
  served.

  I'm going to change one line in a file it depends on."

DO: add a line to supabase/config.toml. Save. Say nothing for two seconds.

DO: read the same document again.

SAY:
  "Refused. 'A declared dependency of this document changed after it was
  verified.'

  Nothing re-ran. No pull request, no workflow, no model, no network call. I

  just a hash — microseconds.

  That's the difference between a gate that protects your next commit and one
  that protects the answer you're getting right now."


03:25–04:10 — WHO CHECKS THE CHECKER?
------------------------------------------------------------------------------
ON SCREEN: the write-path architecture, then docgov/agents.py and the failing
ungrounded-token test.

SAY:
  "Letting AI update documentation creates the exact risk we're trying to stop:
  confident false memory. So who checks the checker?

  Doc Governor uses four constrained Strands roles across two workflows. The
  Repair Planner handles the repetitive pre-commit plan. A separate three-agent
  governance graph audits evidence, resolves conflicts, and drafts only eligible
  contract spans. The separation is about privilege, not speed.

  The Evidence Auditor judges whether the evidence supports a document's claims.
  It is deliberately not shown the document's own status line or its verified
  date. A document that says 'verified' is trying to answer the question you're
  asking it about.

  The Contract Drafter is the only one that can propose new prose. It cannot be
  constructed at all for a status document, an evidence record, or protected
  content — that raises an error in code, not a rule in a prompt.

  And every identifier it writes has to appear literally in a source file it
  cites. If one doesn't, the whole draft is thrown away and the document is
  refused instead."

ON SCREEN: the failing test for an ungrounded token.

SAY:
  "Here's a test proving an invented function name gets the entire draft
  discarded."


04:10–04:35 — DRIFT, AND THE AWS BOUNDARY
------------------------------------------------------------------------------
ON SCREEN: the drift_findings line, then PRODUCTION.md flipping to refused.

SAY:
  "Last one. If somebody changed production from a dashboard instead of through
  the release flow, then production is in a state no commit produced — so every
  document describing production stops being readable. Read-only: it reports,
  it never deploys.

  On AWS: no long-lived keys anywhere. GitHub trades a short-lived identity
  token for temporary credentials, and that role can invoke only Amazon Nova
  Lite through one inference profile. Pull requests from forks get no AWS
  identity at all."

  Doc Governor stops AI-generated documentation from becoming false memory."
